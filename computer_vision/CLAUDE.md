# computer_vision/: PAUL vision module

Camera-based assistance for PAUL: an operator drives a LeRobot SO-101 arm through an IMU armband, and this module watches the wrist camera, picks a target and publishes guidance. Product context is in `../README.md`; how to run and tune this module is in `README.md` here; what is not built or not verified yet is in `NOT_BUILT.md`; the original brief is in `KICKOFF_PROMPT.md`.

## Rules that do not bend

- **Vision assists the operator; it never controls the arm.** It must never open the servo bus.
- Vision never touches audio. It publishes `summary` text; another process speaks it.
- **Never emit misleading guidance.** When unsure, publish `low_confidence` or `no_target`; when the feed stalls, `degraded`.
- Every threshold and tuning value lives in `config.yaml`. None are hardcoded.
- Work only inside `computer_vision/` unless told otherwise.
- Ask before adding a dependency. Do not add `opencv-contrib-python`: it overwrites the `cv2` that Ultralytics depends on, and `opencv-python` 5 already has `cv2.aruco`.
- For Ultralytics, OpenVINO, pyzmq, OpenCV and uv, check current docs through Context7 before writing code against them. Several APIs here differ from older versions (see Gotchas).

```powershell
uv run python -m paul_vision.send_command tag_visual my flask  # [--bbox x1,y1,x2,y2]; or: tag_text <name> [--prompt ...], untag <name>
uv run python -m paul_vision.labels list             # the operator's tags; remove <name>, rebuild [--backend] (vision stopped)
uv run python -m paul_vision.voice                   # utterances (typed or piped, wake word first) to commands; --say, --listen, --grammar
uv run python scripts/voice_loopback.py              # measures the --listen stand-in without a microphone (--work-dir for the wav files)
uv run python scripts/make_markers.py                # print-ready station markers in markers/
uv run pytest                                        # no camera, GPU or pads needed
uv run python scripts/eval_clips.py sample_videos    # report on recorded clips (objects only)
uv run python scripts/list_cameras.py                # find the camera index
..\demo.ps1 -ServicesOnly                            # the team launcher: bridge, vision and console (README, "The team launcher")
```

On NVIDIA machines every `uv run` needs the selected CUDA extra: `--extra cu128` on the tested driver 573.91 machine, or `--extra cu130` for a CUDA 13-compatible driver. A plain `uv run` re-syncs to the CPU build of PyTorch.

Environment: Python 3.12, uv (not a package; run from this folder), Windows. Two detector profiles are chosen at startup and printed in a banner: `torch on CUDA` (demo machine) and `openvino on Intel GPU` (laptop, CPU as fallback). Both use `yoloe-26s`. The station markers run on the CPU through OpenCV in both.

## The `vision` message

The publisher binds `tcp://127.0.0.1:5555`; subscribers connect. One ZMQ frame per message: topic, a space, compact JSON. A single frame lets a subscriber set `zmq.CONFLATE`.

```
vision {"t":1731542400.123,"frame_id":1042,"status":"ok","phase":"approach","target":{"track_id":7,"label":"cup","source":"yolo","bbox":[0.41,0.3,0.62,0.58],"confidence":0.91},"guidance":{"dx":-0.12,"dy":0.05,"distance_hint":"near","aligned":false},"summary":"Cup near, slightly left.","alert":null}
```

Exactly these eight keys, always:

| Field | Rule |
|---|---|
| `t` | Capture time of the frame, Unix seconds. Not the publish time. |
| `frame_id` | Sequence number from the source; gaps are skipped frames. |
| `status` | `ok` (target locked), `low_confidence` (a candidate visible, none sure enough to lock), `no_target` (no candidate of the phase's domain visible), `degraded` (no fresh frame; sent by the watchdog every `watchdog.heartbeat_s`). |
| `phase` | `search`, `approach`, `grasp`, `carry`, `place`, `release` (`phase.PHASES`). A `degraded` heartbeat repeats the last published phase (`search` before any). |
| `target` | `null` unless `status` is `ok`. `label` is a detector class, a tag name the operator taught (never the internal `<name>#<k>`), or `drop station`. `source` is `yolo` or `aruco`. `bbox` is `[x1, y1, x2, y2]`, each 0 to 1, 4 decimals, strictly `x1 < x2` and `y1 < y2` (`messages.wire_bbox` widens a span that rounding collapsed to one step of 0.0001). `confidence`: YOLOE's score, or OpenCV's rating of the marker read. |
| `guidance` | `null` unless `status` is `ok`. `dx`, `dy` in −1..1, target centre minus frame centre, positive = right / down in gripper terms. `distance_hint`: `far`, `near`, `in_reach`. `aligned`: inside the deadzone. |
| `summary` | A sentence to speak, or `null` when nothing new is due. |
| `alert` | `null` or `"dropped"` (`phase.ALERTS`), independent of `status`. Repeated on every message for `phase.alert_hold_s` after contact is lost in `carry`. Heartbeats carry `null`. |

Consumers act only on `status == "ok"`, treat silence or a `t` older than 0.5 s as no guidance (the watchdog cannot report its own process dying), and read `alert` on every message whatever the status.

`paul_vision.messages` owns the contract: `build_vision_message`, `wire_bbox`, `encode`, `decode` (raises `ValueError` for anything it cannot read: not UTF-8, not JSON, or JSON nested too deeply), `validate_vision` (rejects a missing or extra key), `is_number` (a finite int or float, not a bool, and small enough for a float; `commands.py` uses it for a box), and for the pressure topic `TOPIC_PRESSURE`, `build_pressure_message`, `validate_pressure`, and `TOPIC_ROBOT` for the arm controller's topic (its payload is checked in `gripper_load.reading_from_robot`). Change the contract there, then in `tests/test_messages.py`, `README.md` and here.

Other topics (the publisher of each topic binds; endpoints are in `config.yaml`; payloads are in `README.md`):

- `command`: consumed by `commands.py` from every entry of `transport.command_sub` (5557 the console bridge, 5559 the voice process `voice.py`, 5560 `send_command`). `select_target` (a detector class or a live tag name), `clear_target`, `set_phase`, and the label commands `tag_visual`, `tag_text` and `untag`, which go to `label_manager.py`; other types are ignored.
- `pressure` on 5556: consumed by `pressure.PressureReceiver`; published by `pressure_bridge.py` or `mock_pressure.py`. `{"t", "raw": [4], "norm": [4]}`, pads in the order left tip, left base, right tip, right base.
- `robot` on 5558 (`transport.robot_sub`): published at 10 Hz by the arm controller (`../leslider_control/telemetry.py`, `RobotTelemetry` and `robot_message`), which the team launcher starts; consumed by `gripper_load.GripperLoadReceiver`, only with `gripper_load.enabled`. `{"t", "pos": [6], "load": [6] | null, "control": {"input", "enabled", "input_fresh", "feedback": "measured" | "preview", "target"}}` (the leslider controller adds `slider`), joints in the order shoulder pan, shoulder lift, elbow flex, wrist flex, wrist roll, gripper; `load` is each servo's load / 1000, null when the bus read failed; `t` is the controller's `time.time()`.

## Pipeline

`app.Pipeline.process(frame, contact)` runs one frame through every stage and returns the message:

```
FrameSource -> CompositeDetector (YOLOE + ArUco) -> IouTracker -> PhaseMachine.update_contact -> TargetSelector.set_domain
    -> TargetSelector.update -> GuidanceFilter -> PhaseMachine.update_vision -> Summarizer -> build_vision_message
                                                                                                    |
                                                   VisionPublisher (own thread, owns the socket, watchdog)
```

The phase is decided in two steps per frame: first from the pads and `set_phase` (`update_contact`), because the phase decides what may be the target (`phase.target_domain`: objects, or the drop station in `carry` and `place`); then from the target's distance hint (`update_vision`: place, leaving place, the blind spot, events and the alert). `app.run()` polls the grip feed (`PressureReceiver`, or with `gripper_load.enabled` a `GripperLoadReceiver`, into the `ContactDetector` passed as `run(..., contacts=)` or else built from `cfg.pressure`; every reading since the last pass) and the command feed on every pass of its loop, frames or not, and hands the current `Contact` to `process`. It also calls `labels.poll()` (the `LabelManager`) on every pass and `labels.observe(frame, result)` after every processed frame. A finished label change is applied in `poll()`, between two frames: `UltralyticsDetector.adopt` swaps the class list, `Pipeline.labels_changed` makes the tracker forget its label votes (`IouTracker.forget_labels`) and, when the target was narrowed to another label and the locked track comes back under the new name, narrows to the new name so the lock is kept, and the manager's answers reach `summary` on the next message through `Pipeline.announce`. `announce` stamps each sentence with the time (`Pipeline(cfg, detector, *, now=clock.now)`); one more than `watchdog.stall_timeout_s` older than the next frame (the feed stalled or was paused) is logged as `announcement dropped, ... s old when the next frame came: ...` and not spoken, because a late answer would be taken for the answer to a newer command. At startup `__main__` runs `label_manager.prepare_startup` (which may rebuild the library or build its OpenVINO export, in the foreground) before `create_detector(..., views=...)` builds the detector with the library's views. A gap longer than `watchdog.stall_timeout_s` resets tracking but keeps the phase; `Pipeline.reset()` (a camera switch) resets the phase too.

| Module | Role |
|---|---|
| `types.py` | `Frame(image, t, seq)`, `Detection(label, confidence, bbox, source)`, `Track(track_id, ...)`, `Guidance`, status constants. Boxes are normalized `[x1, y1, x2, y2]` in the oriented frame. |
| `geometry.py`, `clock.py` | Box helpers (`center`, `area`, `iou`, `center_distance`, `clamp`); `clock.now()`, Unix time with sub-millisecond resolution. |
| `sources.py` | `CameraSource` (background thread, newest frame only, reopens a dead camera after `reopen_after_s`, but allows a newly opened one `first_frame_s`), `VideoFileSource` (paced replay; `exit`, `loop` or `hold` at the end), `orient()`. Orientation is applied to the image here, once, before anything else sees it. |
| `camera_control.py` | `CameraControl`: lists cameras without opening them and switches to another between two frames, for `stream.py`'s `/sources` and `/source`. The old source keeps streaming until the new one delivers; a failed switch changes nothing. Off with `--record`. |
| `detector.py` | `Detector` protocol: `detect(image) -> list[Detection]`. `resolve_profile` picks torch or openvino; `UltralyticsDetector` runs YOLOE with `detector.classes` followed by the label library's views (each view is one model class `<name>#<k>`, reported as `<name>`); `CompositeDetector` runs YOLOE and the station detector on the same image and keeps per-detector `timings` (`detect yolo`, `detect aruco` in the log line). The class list changes while frames run in two steps: `prepare(views)` on any thread returns a `PreparedClasses` (torch: the prompt embeddings; OpenVINO: the new export, loaded, compiled and run twice) without touching the serving model, and `adopt(prepared)` swaps it in on the frame thread between two frames. `adopt` never calls `YOLOE.set_classes` (see Gotchas). |
| `aruco.py` | `StationDetector`: the pick (id 9) and drop (id 15) markers from `DICT_4X4_50`, as `Detection`s with `source="aruco"` and labels `pick station` / `drop station`. Filters for false stations: only the two ids, `min_side`, `min_side_ratio`, `min_confidence`, exact bit matches. The box is not the marker's outline: `square_box` makes a square of the mean of the four sides (`marker_sides`), centred where the diagonals cross (`marker_centre`), so turning the marker in the image leaves the distance hint alone, while a marker tilted away from the camera reads somewhat further than it is. A square that sticks out of the frame is moved back inside at full size; only one larger than the frame is cut. A mirrored marker is another code (the drop marker, id 15, does not read at all), so when the camera settings mirror the picture (`mirrors_picture`: exactly one of `camera.flip_h` and `flip_v`), `__main__` builds `StationDetector(cfg.stations, mirrored=...)` with it true: each frame is also searched flipped left to right, the boxes of that search are flipped back (`mirror_box`), and per station the search with the better read wins (`best_reads`). |
| `bake.py` | Class list to prompt embeddings (`.npz`) and an OpenVINO export, keyed by weights, classes and input size, under `models/`. |
| `tracker.py` | `IouTracker`: greedy IoU match, then nearest centre, only between a track and a detection of the same `source`. For objects matching ignores the label; a track's label is decided by a confidence vote (`label_memory_s`, `label_margin`). Sources in `IDENTITY_SOURCES` (only `aruco`) are the exception: their label is the decoded id, so a detection continues only a track of its own label, and such a track is never renamed. `forget_labels()` clears the votes when the detector's class list changes. |
| `selection.py` | `TargetSelector`: lock at `conf_lock`, keep at `conf_keep`, switch only to a rival that leads by `switch_margin` for `switch_dwell_s`, coast for `coast_s` over missed frames. `set_domain()` chooses the candidates: objects (never a marker, narrowed by `set_preferred_label()`) or only the drop station. The pick station is never a target. Status counts the domain's candidates only, so a cup in view during `carry` is `no_target`. |
| `guidance.py` | `GuidanceFilter`: offsets, time-constant smoothing (resets when the target changes), deadzone and distance hint with hysteresis. Station labels have their own `distance.thresholds`. |
| `summary.py` | `Summarizer`: sentence templates; a sentence must be new, stable for `settle_s`, and `min_interval_s` after the last one. What is said depends on the phase (`carry`: the drop station, else "Looking for the drop station."). The phase events ("Grip established.", "Released.", "Grip lost. Object may have dropped.", "Grip sensor lost.") are spoken at once, past the settle time and the rate limit. So are `notices`, the label manager's answers ("Learning my flask.", "My flask is ready."), after any events in the same utterance; a notice is not the scene's sentence, so a scene sentence that is due still follows, at least `min_interval_s` later. `Pipeline` passes only the notices that are still current (see the pipeline paragraph above). |
| `phase.py` | `PhaseMachine`: the six phases, the `dropped` alert, the blind spot, sensor loss, and `force()` for `set_phase`. Unknown or stale pad data never gives grasp, release or a drop. Transitions and timings are in `README.md` under "Phases". |
| `pressure.py` | `grip_level` (the `combine` rules), `normalize` (calibration), `ContactDetector(cfg, level_of=None)` (thresholds with hold times; `level_of` turns a reading into the level, by default `grip_level` of the pads, and `cfg` needs only the thresholds, holds and `stale_s`, so the `gripper_load:` section fits too; a `stale_s` property; `update()` replays every reading it is given on that reading's own `t`; contact is unknown when two consecutive readings are more than `stale_s` apart or the newest is older than `stale_s`), `FeedReceiver` (one topic on one SUB: parses each message into a reading, counts messages without one and invalid ones, throttles its warnings) and its subclass `PressureReceiver` (vision side: `poll()` returns every valid reading since the last call, in arrival order, as a list, or `None`), `PressurePublisher` (used by the mock and the bridge). |
| `gripper_load.py` | Contact from the gripper servo's load while no pads publish. `reading_from_robot` (pure: a `robot` payload to a `GripReading(t, level, load, pos)`, with `level = clip(sign * load[gripper], 0, 1)`, and 0 within `empty_margin` of `empty_pos`; `None` for `load: null` or `feedback: preview`; `ValueError` for a message the controller would not build), `GripperLoadReceiver` (a `FeedReceiver` on `transport.robot_sub`, `kind = "load"` for the overlay) and `grip_level_of`, for `ContactDetector(cfg.gripper_load, level_of=grip_level_of)`. `__main__` uses them instead of the pads with `gripper_load.enabled`. |
| `mock_pressure.py` | Stand-in publisher for the pads: console keys, `--script` steps with ramps, or `--replay` of a log. |
| `pressure_bridge.py` | Serial lines to `pressure` messages: `parse_line` (the assumed format), `LineSplitter`, `PressureBridge` (calibration, skip counts, status line), `run_bridge` (reopens a lost port). pyserial is imported lazily in `_serial()`. |
| `transport.py` | `VisionPublisher` (thread, queue, `Watchdog`; heartbeats repeat the last published phase), `Subscriber` helper (one endpoint or a list, on one SUB socket). |
| `commands.py` | `CommandReceiver`: subscribes to `command` on every `transport.command_sub` entry, polled once per pass of the main loop. `apply_command` dispatches by `type` through `CommandHooks`: `select_target` and `clear_target` call `set_preferred_label()` (`hooks.classes` is a list or a function, so live tag names count), `set_phase` calls `Pipeline.set_phase()`, and `tag_visual`, `tag_text` and `untag` become a `LabelRequest` (`parse_label_request`, which never raises; an unusable payload sets `problem`) for `hooks.teach`, which is `LabelManager.teach`. A box needs four numbers that `messages.is_number` accepts (finite, not a bool, small enough for a float), else "Cannot learn X: the box is not valid.". Anything it cannot honour exactly is logged and ignored, and `apply_command` never raises: an unexpected error is logged as `command of type ... could not be applied; ignored`. Vision never reads a command's `t`. |
| `labels.py` | The label library under `labels.dir`: `library.json` (written atomically), view embeddings in `views-<hash>.npz`, the reference pictures in `refs/`, the OpenVINO export per class list in `openvino/`, and `library.next.json` for a change that is built but not live, or live but not saved yet. Also the name rules (`normalize_name`, `name_problem`), `stale_reason` (the library was made for other weights or another `imgsz`), `read_tag_names`, and the offline commands `list`, `remove`, `rebuild`. Imports no torch, Ultralytics or OpenCV, because the voice process and `send_command` read the names from it. |
| `label_manager.py` | `LabelManager`, on the frame thread: one change at a time. `teach()` checks a request against the newest frame and the library and answers at once, saves the picture and starts the label worker at low priority; `poll()` follows the worker, has a thread run `detector.prepare` on its result, then applies it between two frames (`_apply`: `adopt`, `library.next.json` becomes `library.json`, `Pipeline.labels_changed`, "My flask is ready."). `labels.worker_timeout_s` and `labels.load_timeout_s` bound the two waits. A change that went live but whose rename to `library.json` failed stays in `library.next.json` (`_unsaved`): `_start` tries the save again before a new change (every worker starts from `library.json`), and refuses the new change while it still fails ("Cannot learn X: the change to Y could not be saved yet."); `close()` tries once more; `poll()` does not retry. `teach()` and `poll()` never raise an `Exception`: an unexpected one is logged and ends the change as failed ("Could not learn X.", with "that" for a name that was not checked). `prepare_startup()` rebuilds a stale library or builds a missing OpenVINO export before the first frame; `run_blocking()` is the same worker run in the foreground, for that and the offline commands. |
| `label_worker.py` | The child process for one change (`python -m paul_vision.label_worker <job.json>`): loads YOLOE in PyTorch on the CPU with `labels.worker_threads` threads, makes the view's embedding from a box on a saved picture or from a text prompt, writes the library files, and on OpenVINO builds the export for the new class list. Writes a result file; its log is kept in `<labels dir>/jobs/` (the last 10). It exists because model work inside vision stalled frames for 557 to 816 ms. |
| `send_command.py` | Sends one command from a terminal: binds the last `transport.command_sub` entry as an XPUB, waits until vision has subscribed, sends once. Covers all six types: `tag_visual <name> [--bbox x1,y1,x2,y2]`, `tag_text <name> [--prompt ...]`, `untag <name>` besides the three above. A `select_target` label is checked against `detector.classes` and the tag names in the library. `XPUB_VERBOSE` reports every subscription, and it counts each one to a prefix of `command ` (the empty prefix of a subscriber to everything included) in "sent to N subscribers". For a tag command, vision's "My flask is ready." means the model that knows the name serves frames, whether or not the object is in view. A configuration that cannot be loaded prints `send_command: configuration: ...` and exits 2. |
| `voice.py` | The voice process (M5), a program of its own: utterances as text in, `command` messages out on `voice.endpoint`. `parse_utterance` (pure: wake word, fillers, verb phrases, phases, tag names; a new name that holds a wake word or is a command itself is refused, `_command_in_name`) and `match_label`. `match_label` compares labels as they are said (`spoken_form`: "mug (red)" is "mug red"; two labels said the same way are refused): as said, without determiners, singular, then `difflib` with `voice.label_cutoff` and `voice.label_margin`, but only against labels the words could be misheard from (`_not_misheard`: the same numbers; with as many words, each word equal, a plural, or at least `label_cutoff` similar, and a one-letter word equal). It never guesses between two labels, and a refusal names the closest label and its score. `untag` matches the tag name as said. `VoiceSession.tags()` leaves out tag names voice cannot use, with one warning naming `library_file` (`main` passes `labels/library.json`). `CommandPublisher` binds an XPUB with `XPUB_VERBOSER`, so it knows whether a subscriber is there, and sends only then (otherwise NOT DELIVERED; nothing is queued). Inputs: stdin lines, `--say`, and `--listen` (`StandInRecognizer`: `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File scripts/voice_listen.ps1` with a grammar from `listen_grammar`, which adds `voice.listen.decoy_words` beside the wake words and the labels; when the tags change, `run_listen` stops the recognizer and starts a new one with the new grammar). A configuration that cannot be loaded prints `voice: configuration: ...` and exits 2. Imports no torch, Ultralytics or OpenCV; plays no audio. |
| `stream.py` | The camera picture for the web console, MJPEG over HTTP on `stream.port`, plus `GET /sources` and `POST /source` (local origin only). `submit` only swaps a reference; encoding happens on its own thread, once per picture, and only while someone is watching. |
| `overlay.py`, `metrics.py` | Debug window (status line with the phase and `(set)` for a forced one, the grip line (`grip (load)` for the gripper load), stations in magenta, the `ALERT` banner); FPS and per-stage timing. The message is published before the overlay is drawn. |
| `app.py` | `Pipeline` (with `announce()` for the label manager's sentences and `labels_changed()` after a class-list change), `Recorder` (encodes on its own thread), `run()` main loop. |
| `config.py` | Frozen dataclasses mirroring `config.yaml`; unknown or missing keys are errors; `validate()` checks ranges. `load_config` raises `ConfigError` (a `ValueError`) for a file that is not UTF-8 or not valid YAML, naming the file and, for YAML, the line and column; for an invalid config the message names the key, not the file. A file it cannot open raises `OSError`. Vision, voice and `send_command` print either as one `configuration: ...` line and exit 2. |

All of tracker, selection, guidance, summary, phase, the contact decision in pressure and messages are pure (no I/O, time passed in as `t`), which is why they can be tested and replayed deterministically. So is the voice parser (`voice.parse_utterance` and `voice.match_label`).

## Adding or changing a config key

1. `config.yaml`: the key with a comment that says what it does.
2. `paul_vision/config.py`: the dataclass field, and a range check in `validate()` if it has one (the `phase:`, `pressure:`, `gripper_load:`, `labels:` and `voice:` checks are in `validate_phase_config`, `validate_pressure_config`, `validate_gripper_load_config`, `validate_labels_config` and `validate_voice_config`).
3. Tests: each logic test file builds its own config object (`CFG = TrackerConfig(...)` and so on), so tuning `config.yaml` never breaks a test. Add the field there, and a test for the behaviour. The end-to-end, overlay and config tests load the shipped `config.yaml`.

M2 added `StationsConfig` (`stations:`), `PhaseConfig` (`phase:`) and `PressureConfig` (`pressure:`, with `calibration`, `mock` and `bridge`), station entries in `distance.thresholds`, and made `transport.command_sub` a list. M4 added `LabelsConfig` (`labels:`: the library folder, the limits on names, views and boxes, the worker's threads and the two timeouts). M5 added `VoiceConfig` (`voice:`) with `VoiceListenConfig` (`voice.listen:`, the stand-in recognizer); `validate_voice_config` refuses a `voice.endpoint` that is not one of `transport.command_sub`, because vision would never hear it. The gripper load added `GripperLoadConfig` (`gripper_load:`); `validate_gripper_load_config` wants `sign` 1 or -1, `0 <= off_threshold < on_threshold <= 1`, holds of 0 or more, and `stale_s` above 0.1 s, the controller's telemetry period.

- `uv run pytest`: pure logic per module, plus `test_pipeline_e2e.py` (a fake detector through the real pipeline and real ZMQ). M4's tests are `test_labels.py` (the library files and the offline commands), `test_label_manager.py` (a fake worker and a fake detector, so no model is loaded; three tests run the real `label_worker.run_job` with a stand-in model and text encoder) and `test_label_pipeline.py` (label changes through the real `Pipeline` and `run()`, with a fake detector); M5's are in `test_voice.py` (the parser, the publisher on real ZMQ, the grammar; no microphone and no PowerShell). - A few tests run in real time on real sockets and can fail on a heavily loaded machine without a defect; rerun them alone before suspecting a change. In `tests/test_mock_pressure.py`, `test_main_script_mode_publishes_the_curve_and_logs_it` needs 25 of the 31 samples of a 0.3 s script (the mock does not catch up after a stall, so less than 0.1 s of stalls fails it), `test_run_levels_over_zmq_turns_contact_on_then_off_at_the_set_rate` needs 85 % of the rate, and `test_replay_keeps_the_original_timing_over_zmq` needs the replay to take under 0.45 s; in `tests/test_camera_api.py`, `test_a_client_that_withholds_or_floods_the_body_does_not_hold_the_server` needs the answer, and the close after a flood, within 0.4 s. The tests of the last sample and of `--replay` with `--duration` run on a fake clock (`FakeTime`) and do not depend on load; the other staged-close tests check only the answer, sent after a fixed 50 ms pause.
- `scripts/eval_clips.py <clips or folders>`: runs the real object detector and pipeline over recorded clips, every frame, on the clip's own clock, so results do not depend on machine speed. No station markers and no pads, so only `search` and `approach`. Prints per clip: status shares, target labels, locks and renames, and every sentence with its time. `--sheets DIR` saves annotated stills. Run it before and after changing a threshold or the class list.
- `sample_videos/`: 17 wrist-camera clips from public SO-100/SO-101 datasets (not in git; sources in `sample_videos/README.md`). They are not our camera or our objects. Record our own with `--record` once the camera is on the arm.
- A bench run of the whole M2 loop without hardware: vision, `subscribe_print`, `mock_pressure` and `send_command` in four terminals (`README.md`, "A bench run without hardware"). To run it beside a live vision, copy `config.yaml` with other ports and pass `--config` to all four.

What the sample clips showed (numbers in `README.md`):
- An upright cup seen from the front works well: one steady lock, the right name, sensible sentences.
- The same object gets different labels from different sides. A pill bottle is "bottle" from the side and "cup" cap-first; "pill bottle" is almost never the label. The label vote reduces renames; it cannot make the name right.
- Objects that fill the frame, cups lying on their side under a tilted camera, small blocks and trays, and dark or blurred scenes are detected poorly or not at all. The phases cover the first with the pads (`phase.blind_spot_s`).
- No clip has a station marker in it. On the 17 clips plus `recordings/run1.mp4` (17,501 frames), the shipped `stations:` settings reported no station.

## Gotchas

- **Bake before first run and after changing classes, weights or `imgsz`.** The first bake downloads weights (30 MB) and a text encoder (243 MB) and needs git for the `clip` package. Runtime then needs no network. A mismatch between the loaded model and `detector.classes` stops startup with the fix in the message.
- **Ultralytics sets OpenCV to one thread when imported.** `UltralyticsDetector` restores the default after warm-up (`cv2.setNumThreads(-1)`); without it the overlay resize and video writing are several times slower.
- **Half precision is `quantize=16`** in this Ultralytics version, not `half=True`.
- **YOLOE checkpoints are `-seg` models.** `bake.py` loads them with a detection head so no masks are computed.
- **ArUco in OpenCV 5.** `aruco.py` uses `cv2.aruco.ArucoDetector(dictionary, DetectorParameters())`, not the older module-level functions; check Context7 before changing it. `detectMarkersWithConfidence` (new in OpenCV 5) returns a per-marker confidence, which is what `target.confidence` carries for a station. `minMarkerPerimeterRate` counts contour points, not pixels, so `aruco.py` gives it slack and checks the exact size after decoding. `errorCorrectionRate` stays 0: one tolerated bit would have read a scene sliver as the drop station.
- **Print markers at 100 %.** A sheet printed "fit to page" is smaller than its caption says, and every distance threshold assumes the printed size. `markers/` is gitignored; regenerate after changing `stations.dictionary` or the ids.
- **Camera format order on Windows.** With DirectShow, set the resolution first and MJPG after it, or the driver falls back to YUY2 at 10 FPS. `sources.open_capture` does this and logs the format it got.
- **A camera's first frame can take over a second.** The laptop's built-in camera needs 1.1 s. Reopening it after `reopen_after_s` (1.0 s) never let it start, which is why `camera.first_frame_s` exists and must not be below `reopen_after_s`.
- **The integrated GPU is shared.** A browser playing video can halve the frame rate on the laptop. Close it for any measurement.
- **Time.** Stamp frames with `clock.now()`, not `time.time()`: before Python 3.13, `time.time()` on Windows only ticks every 15.6 ms. `clock.now()` is Unix time with sub-millisecond resolution. Pad staleness is judged on each reading's own `t`, which the mock and the bridge stamp with `clock.now()` on the same computer; a publisher on another clock would break it.
- **USB serial on Windows arrives in bursts.** That is why `pressure.stale_s` is 0.25 s (12 samples at 50 Hz). Much shorter values make contact flicker to unknown. How often `app.run()` reads the pads does not change the decision: `PressureReceiver.poll()` hands over every reading since the last pass and `ContactDetector` replays them on their own `t`, so a slow pass only delays the decision. `run()` still waits at most `stale_s / 2` for a frame, so the pads are read at least that often while frames stall. A grip and a let-go inside one pass are both replayed, but the phase machine sees only the state at the end of the pass.
- **The publisher thread owns the socket.** Other threads call `publish()`, which only queues.
- **Only one process can bind a port.** The pressure mock and the bridge share 5556, so only one runs at a time. Each command sender has its own entry in `transport.command_sub`; a new sender needs a new entry there, or vision never hears it. `send_command --endpoint` cannot bind the voice process's 5559 while voice runs.
- **ZMQ slow joiner.** A message published before the subscriber has connected is lost. `send_command` binds an XPUB and waits for the subscription (`XPUB_VERBOSE`) before sending. The voice process, which stays up while vision comes and goes, uses `XPUB_VERBOSER`, which also reports unsubscribes, so it knows when nobody listens any more; with no subscriber it waits up to `voice.deliver_wait_s` for one and then drops the command instead of queueing it. Anything else that sends commands must do one or the other.
- **`stream.py` closes a connection in stages.** A request refused before its body is read (403, 404, 503, or 400 for the content type or a body over 1024 bytes) leaves that body unread, and closing a socket with unread data resets the connection; on Windows the client then lost the answer (`ConnectionAbortedError [WinError 10053]`, the old flake in `tests/test_camera_api.py`). So `_Server.shutdown_request` ends the answer (half-close), reads and drops what the client still sends until it closes its end, at most `_LINGER_MAX_BYTES` (64 KiB) for at most `_LINGER_S` (2 s), and only then closes. As a result, a client that connects and sends nothing holds its handler thread for the 5 s request timeout (`_SEND_TIMEOUT_S`) and up to 2 s more, and a viewer that keeps its socket open after the stream stops keeps its daemon thread up to 2 s longer; `FrameStream.close()` waits for neither.
- **pyserial is imported lazily** in `pressure_bridge._serial()`, and an unrelated PyPI package named `serial` is rejected. Without pyserial the bridge prints the fix and exits with 3; nothing else needs it.
- **A forced phase never falls back on pad loss.** `set_phase grasp`, `carry` or `place` holds without pad data, and the pad state at the moment of the command is not news. If the pads are undecided, stale or silent then, the first state they decide afterwards takes that place: it is the baseline, not news, so it does not start a grasp. Only phases the pads started fall back after `phase.sensor_loss_hold_s`.
- **A camera switch resets the phase; a stall does not.** The stall keeps it so a camera hiccup during `carry` is not a drop.
- **A mock `--script` that ends right after a level change reads as sensor loss**, not as an open gripper: the pads go silent before `off_hold_s` has passed. End scripts with a hold step.
- **`IDENTITY_SOURCES` is only for decoded labels.** A source listed there never renames a track, so a detector that guesses its labels (YOLOE) would keep a wrong first label forever. Only the markers, whose label is the id they decoded, belong in it.
- **Model work belongs in the label worker, never in vision.** Building or exporting a YOLOE model inside the vision process stalled the frame loop for 557 to 816 ms, past the watchdog. Anything heavy a command starts goes to a child process (`label_worker.py`) at low priority with `labels.worker_threads` torch threads, and vision only polls it.
- **Never call `YOLOE.set_classes` on a model that serves frames.** It drops the predictor, and rebuilding that on the next frame took 382 to 596 ms. `UltralyticsDetector.adopt` sets the classes on `model.model` and on the predictor's own copy instead. (The constructor calls `set_classes` once, before any predictor exists, which is cheap.)
- **An OpenVINO export has its classes built in.** On the OpenVINO profile every tag change is a new export, made by the worker, then loaded and compiled by vision on a thread while the old model keeps serving (`labels.load_timeout_s`). On torch only the prompt embeddings change, and `adopt` swaps them between two frames.
- **The label library belongs to one weights file and one `detector.imgsz`.** Its embeddings fit only those. After a change to either, the next start rebuilds the library from its saved pictures and prompts (seconds, before the first frame); if that fails, vision stops and names the `labels` command that fixes it. The weights file it checks is the one of the profile in use (`detector.weights.torch` or `detector.weights.openvino`); both are `yoloe-26s-seg.pt` now, and different files there would make every profile switch a rebuild.
- **`labels/` holds camera pictures and is gitignored.** Tags do not travel with the repo.
- **Only one process may change the library at a time.** While vision runs that is its label worker; `labels remove` writes `library.json` itself and does not check whether vision is running, so while vision runs send `untag` instead. Nothing detects a second vision on the same `labels.dir` either (`NOT_BUILT.md`).
- **Windows refuses to replace a file another process has open for a moment.** `labels._replace` retries `os.replace` (`REPLACE_TRIES` 5 times, `REPLACE_PAUSE_S` 0.01 s apart), because the voice process and `send_command` read `library.json` while vision writes it.
- **`voice.py` must not import torch, Ultralytics or OpenCV.** It started in about 0.3 s on the idle dev laptop and runs beside vision; `tests/test_voice.py` checks the imports. That is why `labels.py` needs only numpy, and why `voice.STATION_NAMES` repeats the station labels instead of importing `aruco.py` (a test keeps them equal).
- **"Sent" from the voice process is not "accepted".** It counts every subscriber to `command` (a `subscribe_print` too). Vision can still refuse a label command; it says why in `summary` and in its log.
- **The `--listen` grammar is closed.** The recognizer hears every utterance as the nearest phrase it knows, so a word that sounds like a known one ("cap", "bowl", "paula") came back as cup, bottle or paul at confidence up to 0.99 in the loopback test. Neither `voice.listen.min_confidence` nor the dictation decoy (`voice.listen.decoy`) catches these. `voice.listen.decoy_words` (`[bowl, paula]`) puts listed sound-alikes in the grammar beside the wake words and the labels, never sent: in the loopback test the wrong sends went from 13 to 7 of 102 ("cap" as cup 4 times, "paula" as paul 3 times, at 0.85 to 0.97). "cap" is not listed because it turned 6 of 54 correctly spoken "cup" commands into "cap", and a sound-alike that is not listed ("cop", "cub", "books") is still heard as the label. Rerun `scripts/voice_loopback.py` after changing the phrases, the labels, the decoy words or `voice.listen`.
- **`--listen` runs PowerShell with `-ExecutionPolicy Bypass`.** The full command is `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File scripts/voice_listen.ps1` (an absolute path). The bypass applies to that one process, so the unsigned script runs whatever the machine's policy is, and no setting changes. It needs Windows PowerShell 5.1, where System.Speech lives, not PowerShell 7.
- **Ultralytics sends usage analytics.** By default (`ultralytics/utils/events.py`), when its `sync` setting is true and the machine is online, every process that loads Ultralytics (vision, `bake`, the label worker) sends anonymous events to Google Analytics: the library version, CPU model, device, task and model file name; no images. The documented opt-out is `yolo settings sync=False`. That setting lives in Ultralytics' settings file outside this folder and has not been changed; whether to change it is the team's decision.
- **`--source wrist` is only `camera.wrist_index`.** Without the wrist camera it opens whatever camera has that index (on the laptop, the built-in one) without a warning, and the log says only `source: camera 0`. The team launcher passes `wrist` unless given `-CameraSource`.
- **The team launcher reuses a running service as it is.** A vision already serving the stream on 18766 keeps the config it was started with, its `labels.dir` included; stop it for a new session's `vision.yaml` to apply. The launcher's `--robot-pub-port` is not written into `transport.robot_sub` of that copy either.
- **`robot` messages are stamped with `time.time()`** by the controller, not `clock.now()`; before Python 3.13 on Windows that ticks every 15.6 ms. Against the 0.1 s period and `gripper_load.stale_s` (0.35 s) it does not matter. Staleness is judged on that `t`, so the controller must run on this computer.
- **No git commits from here without being asked.** The repo is shared with the team.

## Neighbouring components

- `../bno085_reader/`: ESP32 firmware that outputs BNO085 quaternions as `w,x,y,z` CSV at 50 Hz over serial (115200 baud).
- `../bridge/`: relays `vision` to the web console over a WebSocket and sends the console's commands on 5557.
- `../frontend/`: the web console. It raises "Object may have dropped" on `alert`, and sends the label commands (the Signals page's "Names" group, and **Draw box** under the camera view).
- `../leslider_control/`: the arm controller, which publishes `robot` on 5558, and the team launcher's session (`session.py`, run by `../demo.ps1`).
- Robot control: LeRobot SO-101 with STS3215 servos.
- Gripper pads: four thin-film pressure pads read by a microcontroller; firmware not written yet.
- Haptics: coin vibration motors on DRV2605L drivers, fed by `guidance`. Nothing acts on `alert` yet.
- Voice: speaks `summary` (no run with it is recorded here). The command side is in this folder: `voice.py` turns utterances, typed or piped in as text, into `command` messages, so the team's speech recognizer, which is not chosen yet, only has to print what it heard (`NOT_BUILT.md`, M5).
- Recording and the live UI consume the `vision` stream alongside the sensor data.
